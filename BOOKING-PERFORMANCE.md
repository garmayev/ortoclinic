# Открытие страницы записи — 28.10.2026

Исходный путь в app-1: Company.get → category/view корневого направления → создание моделей всех вложенных услуг и расписаний → скрытие загрузчика. Данные компании повторно запрашивались после главной. Конструкторы направлений дополнительно запрашивали ту же компанию. Из кода видно, что вся эта загрузка начиналась до выбора направления; наблюдаемые пользователем 12–13 секунд без авторизованного сетевого прогона независимо не подтверждены.

Новый путь включён только при VITE_COMPANY_ID=1 и в синтетическом режиме stand:

- Используются уже полученные в текущем сеансе метаданные компании: название, логотип, ID корневого направления. Смена токена/пользователя/компании исключает использование старых данных. Цены и окна записи в этот кеш не входят.
- При открытии запрашиваются только ID, названия и служебные поля направлений через fields, включая вложенные children. Таймауты и авторизация сохранены.
- Услуги и полные расписания запрашиваются штатным category/view выбранного направления. Продолжить выбор нельзя до окончания запроса. При переходе из истории загружается только сохранённое направление.
- Уже полученная компания передаётся моделям направлений вместо дополнительных запросов.
- Неподдерживаемая проекция (400/422 или некорректная структура) возвращает прежний полный запрос; 401/503 не удваиваются. Пустые списки остаются пустыми; фильтр status не меняется.
- При быстрой смене направлений устаревший ответ не меняет новый выбор. При ошибке можно повторно выбрать направление.

Для других значений VITE_COMPANY_ID сохранён прежний путь загрузки компании и полного каталога. Общий сервер API, другие репозитории, компании, цены, услуги, создание записей и условия расписаний не изменялись.

Проверки: unit-тесты API и компонентов, полные production/stand сборки, интеграционные тесты стенда. В синтетическом каталоге с одним направлением и 1000 услугами полное JSON-тело — 901095 байт, проекция направлений — 220 байт. Все 1000 услуг остаются доступны через полный запрос направления. Это размеры тестовых данных, не замер настоящей клиники и не доказательство ускорения в определённое число раз.

Ограничение: необходим контрольный замер авторизованного запуска в MAX/Telegram после публикации. Если сервер тратит время на построение скрытых связей даже при fields, серверная задержка может сохраниться; изменения общего API без отдельной диагностики не выполнялись. Штатные расписания не удалены, цены не кешируются на диске.

Откат: вернуть предыдущую публикацию app-1 либо предыдущий Git-коммит и заново выполнить штатную выкладку. Для сборки другой компании оптимизированный путь не включается.
