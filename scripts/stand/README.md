# Локальный стенд Medix

Запуск из корня проекта:

```powershell
npm ci
npm run build:stand
npm run stand
```

Открыть http://127.0.0.1:4174/ и выбрать MAX или Telegram. Сервер слушает только loopback. Данные, SDK и API синтетические; это имитация интерфейса мессенджера, а не проверка настоящей подписи initData или нативного WebView.

На стартовой странице доступны два пользователя, ошибка и таймаут SDK, задержки SDK/API, API 503, пустой каталог и 1000 услуг с длинными названиями. Настройки сохраняются в локальной HttpOnly-cookie стенда. Для смены сценария вернуться на корень стенда. При повторном открытии внутренней страницы SDK использует синтетический контекст sessionStorage, как штатные SDK. Не использовать реальные персональные данные.

Создание и отмена записей, регистрация отключены сервером и возвращают 409. CSP запрещает внешние соединения, включая боевой API. Production-сборка не содержит адресов тестового SDK; стенд собирается отдельно в dist-stand с company_id=9001. Обычная команда npm run build создаёт dist с исходной настройкой компании и настоящими SDK/API.

Проверки:

```powershell
npm test
npm run build:stand
npm run test:stand
npm run build
```

Unit-тесты проверяют SDK load/error/timeout/retry, позднюю инициализацию, смену пользователя, запуск вне мессенджера и объединение одновременных запросов с защитой от старого контекста. Серверные тесты проверяют синтетический каталог, 503, известные маршруты, 404 неизвестных файлов/адресов, MIME AVIF, кеш статики и запрет записи. Они не заменяют браузерный прогон.

Ручная проверка: 320/390/768/1280/1440 px, 1280×480, текст 200%; отдельно обе платформы, ошибка SDK и повтор, два пользователя, прямые ссылки /home/services, /home/services/9010, /create и reload. Пройти выбор услуги и диапазона времени без сохранения. В текущем приложении нет отдельного шага выбора врача; добавлять его под видом оптимизации нельзя.

Для замеров фиксировать браузер, устройство, сеть, сценарий, TTFB HTML, первый экран, изображение, готовность авторизации, размеры и число ресурсов/API. Холодный прогон — новый контекст браузера; повторный — reload в том же контексте без отключения кеша. Сценарии задержек одинаковые до/после. Синтетические метрики не описывают производительность настоящего API или нативного клиента.

Production: применять только dist после отдельной проверки реального API и мессенджера. Сохранять предыдущий каталог публикации и конфигурацию сервера; локальный архив исходной сборки расположен в .optimization-baseline/ortoclinic-before.zip. Этот архив не является копией текущей публикации или правил сервера.
